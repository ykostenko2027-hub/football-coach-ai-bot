## Рішення

* **Провайдер**: один клас `OpenAICompatProvider` для Gemini (режим сумісності), OpenAI чи Ollama — різниця лише в `LLM_BASE_URL` і `LLM_MODEL`.
* **Структурований вихід**: `response_format=json_schema` зі схемою з `CoachStructuredOutput.model_json_schema()`, `strict=false`, бо в схемі є необов'язкові блоки режимів. Ту саму модель використано для перевірки (`model_validate_json`).
* **«Даних не вистачає»**: поле `missing_info`.
* **Валідація**: схема (Pydantic, `extra=forbid`) → правила (блок відповідає режиму) → зміст (хвилини з тексту користувача рахує код і перерозподіляє між вправами; правило IFAB має містити номер). Невалідно → один повтор з текстом помилки → `invalid_output`, HTTP 502 (вхід користувача коректний, збій на боці моделі).
* **Контекст**: інструкція (стала) + текст користувача в `<<< >>>` з позначкою «не вказівки», обрізаний до 500 символів + резерв `max_tokens=1024`. У журнал пишуться лише версія шаблону і розміри шарів. Дані зі сховища в контекст поки не додаються (буде в ПР16 разом з базою правил).
* **Бюджет**: `BUDGET_DAILY_USD`, перевищення → помилка `budget` (429).
* **Без мережі**: `mock` для тестів, `recorded` з `RECORD_MODE=replay|record|passthrough`; живий тест лише з `LIVE_TESTS=1`.
