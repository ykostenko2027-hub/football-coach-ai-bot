# Записи архітектурних рішень (ADR)

## ADR-001. Синхронна обробка HTTP-запиту
* **Контекст**: Сценарій генерації тренування або пояснення правила виконує один легкий виклик LLM (`gemini-1.5-flash`) тривалістю $1.0\text{--}2.5$ с.
* **Рішення**: Використовувати синхронний HTTP-контракт (`POST /api/coach/ask` одразу повертає результат) замість фонових черг і опитування статусу (`202 Accepted`).
* **Наслідки**: Значно простіший API та інтерфейс; якщо час перевищить 5 с після додавання RAG, маршрут можна розширити без зміни доменних сервісів.

## ADR-002. Локальне сховище SQLite за абстракцією `BaseStorage`
* **Контекст**: Навчальному проєкту потрібне збереження історії запитів без окремого сервера БД.
* **Рішення**: Реалізовано `SQLiteStorage` зі створенням таблиць кодом, ізольоване інтерфейсом `BaseStorage`.
* **Наслідки**: Нульове налаштування для запуску з чистого клону, легка заміна на тимчасовий файл у `pytest` та можливість переходу на PostgreSQL без змін у `CoachService`.

## ADR-003. Єдиний контракт провайдера з `MockProvider`
* **Контекст**: Потрібно тестувати всю архітектуру й збої до підключення платного API та без витрат токенів у тестах.
* **Рішення**: Введено `BaseProvider` і повноцінний `MockProvider`, керований змінними `.env` (`LLM_PROVIDER`, `MOCK_DELAY_MS`, `MOCK_FAILURE_RATE`, `MOCK_FAILURE_KIND`).
* **Наслідки**: Гарантована перевірка всіх шляхів помилок і валідації JSON без мережі; підключення реальної моделі в ПР15 зводиться до однієї реалізації `BaseProvider`.
