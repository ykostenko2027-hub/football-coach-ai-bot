# Паспорт проєкту: Telegram-бот «Карманний футбольний тренер і експерт»

## 1. Проблема, користувач і сценарій

* **Проблема**: Гравець-аматор тренується самостійно з обмеженим часом (15–30 хв) та випадковим інвентарем (один м'яч, стіна чи пляшки замість конусів). Через брак методики тренування проходять хаотично й без прогресу в техніці. Під час дворових матчів виникають суперечки щодо правил (офсайд, гра рукою), а перед грою бракує психологічного настрою.
* **Користувач**: Футболіст-аматор (14–35 років), який грає у дворі чи аматорській лізі та тренується самостійно без тренера.
* **Основний сценарій (2 хв на захисті)**:
  1. Гравець пише в бот: *«Маю м'яч, стіну і 15 хвилин, хочу покращити перший дотик і слабку ліву ногу»*.
  2. Бот перевіряє запит, модель формує JSON-план, а код перевіряє суму хвилин.
  3. Гравець отримує структуровану картку: розминка (2 хв), 2 вправи біля стіни (по 5–6 хв), заминка (2 хв) і поради щодо техніки.
  4. Гравець тисне кнопку таймера і переходить до виконання на майданчику.
* **Поза межами проєкту (Out of Scope)**:
  1. Комп'ютерний зір і відеоаналіз техніки рухів.
  2. Медична діагностика травм і призначення лікування (заборонено правилами безпеки).
  3. Live-результати та новини професійних футбольних ліг.

---

## 2. Навіщо тут AI (Обґрунтування через Baseline)

* **Baseline без моделі**: Статична таблиця з 15 заготовлених вправ із кнопками вибору та пошук за ключовими словами у тексті правил (FAQ).
* **На чому ламається Baseline**:
  * Неможливо передбачити всі комбінації умов (*«12 хв, дощ, гараж, болить плече»*);
  * Опис спірних ігрових моментів живими словами пошук за ключами не розпізнає й видає загальний юридичний текст замість короткої відповіді.
* **Що додає модель**: Розуміє живу розмовну мову зі сленгом («шведка», «в один дотик»), комбінує вправи під нетипові умови, пояснює правила доступними аналогіями.
* **Де модель небажана**: Підрахунок сумарного часу (математику рахує код), скарги на біль (блокує код-дисклеймер), збереження прогресу (база даних).

## 3. Межа між моделлю, кодом і людиною

| Крок сценарію | Хто виконує | Як перевіряється результат |
| :--- | :--- | :--- |
| **1. Прийом запиту** | Код | Перевірка типу (текст), довжини (10–500 символів) та захист від спаму. |
| **2. Фільтр травм і зламів** | Код | Пошук стоп-слів («біль», «травма», prompt injection). При збігу — видача дисклеймера. |
| **3. Пошук правил (RAG)** | Код (Векторна БД) | Пошук статей IFAB за семантичною схожістю (поріг косинусної близькості $\ge 0.65$). |
| **4. Генерація тренування** | Модель (LLM) | Вихід суворо в JSON. Валідація схеми через Pydantic (поля `warmup`, `drills`, `cooldown`). |
| **5. Перевірка таймінгу** | Код | Перевірка $\sum t_{drills} == t_{total}$. Якщо сума не збігається — автокорекція кодом. |
| **6. Форматування Telegram**| Код | Рендеринг картки з емодзі, екранування символів, інлайн-кнопки таймера. |
| **7. Виконання на полі** | Людина | Гравець контролює самопочуття, запускає вправи або припиняє тренування. |

## 4. Вхід, результат, помилки та критерії якості

* **Вхід**: Текст у Telegram від 10 до 500 символів українською мовою (допускається футбольний сленг).
* **Результат**: Структурований JSON-об'єкт:
  ```json
  {
    "mode": "training | rule_explanation | motivation",
    "workout_plan": {
      "title": "Перший дотик біля стіни",
      "total_minutes": 15,
      "warmup": { "name": "Суглобова розминка", "duration_minutes": 2, "description": "..." },
      "drills": [
        { "name": "Пас правою — прийом підошвою лівої", "duration_minutes": 5, "technique_tip": "..." },
        { "name": "Паси в стіну слабкою ногою в один дотик", "duration_minutes": 6, "technique_tip": "..." }
      ],
      "cooldown": { "name": "Розтяжка литок", "duration_minutes": 2, "description": "..." },
      "safety_note": "Стеж за нерівностями стіни."
    }
  }
  ```
* **Помилки та реакція системи**:
  * *Запит < 10 символів* $\rightarrow$ порада уточнити запит з прикладом (модель не викликається).
  * *Скарга на біль* $\rightarrow$ повідомлення: «При болях тренування заборонені. Звернись до лікаря!».
  * *Збій API моделі* $\rightarrow$ бот видає перевірене закешоване тренування з SQLite.
  * *Невалідний JSON* $\rightarrow$ автоматичний retry або підстановка дефолтної структури.
* **Обмеження**: Час відповіді $\le 3$ с; собівартість запиту $< \$0.001$; персональні дані користувачів не передаються моделі.
* **Вимірні критерії якості**:
  1. **Schema Compliance**: $\ge 98\%$ відповідей моделі успішно валідуються схемою Pydantic.
  2. **Timing Accuracy**: $100\%$ тренувань мають точний баланс часу ($|\Delta t| = 0$ хв після коригувального коду).
  3. **Latency (P95)**: час повної відповіді в Telegram $\le 3.0$ секунд.
  4. **Guardrail Safety**: $100\%$ запитів із травмами та ін'єкціями блокуються детермінованим кодом.

## 5. Вибір моделі та додатковий компонент

* **Основна модель**: **Google Gemini 1.5 Flash**.
  * *Порівняння*: GPT-4o-mini платна з першого запиту; локальна Llama-3-8B вимагає потужного GPU та дає більшу затримку (4–6 с). Gemini має безкоштовний ліміт (15 RPM / 1 500 RPD), затримку $\sim 1.0$ с та надійний Structured Outputs.
  * *Конфігурація*: Назва моделі винесена в `.env` (`LLM_MODEL=gemini-1.5-flash`), що дозволяє змінити провайдера без правок у коді.
* **Додатковий AI-компонент**: **RAG (семантичний пошук)** за офіційними правилами IFAB Laws of the Game 2024/2025.
  * *Як працює*: Запит векторизується через `text-embedding-004`, база ChromaDB знаходить потрібні пункти правил, модель пояснює їх простою мовою без вигадок.
  * *Окрема перевірка (ПР16)*: Тест точності пошуку релевантних статей правил на 10 спірних епізодах ($\text{Recall@3} \ge 90\%$).

## 6. Ризики та оцінка витрат

* **Ризики**:
  * *Якість (галюцинації)*: обмеження промпту + RAG за базою IFAB (ПР15, ПР16).
  * *Безпечність (травми)*: кодовий словниковий фільтр болю та обов'язковий пункт `safety_note` (ПР15).
  * *Захищеність (Jailbreak)*: валідація схеми та перевірка наміру (ПР18, ПР19).
  * *Приватність*: надсилання лише знеособленого тексту без Telegram ID (ПР15).
* **Оцінка витрат**:
  * 1 запит: $\sim 850$ вхідних токенів + $\sim 350$ вихідних токенів $\approx 1 200$ токенів.
  * Вартість 1 запиту за тарифами Gemini Flash: $\approx \mathbf{\$0.00017}$ (частка цента).
  * Для 300 запитів на добу: $\approx \$0.05$/добу.
  * У межах лімітів Gemini Free Tier (1 500 запитів/день) проєкт повністю **безкоштовний (\$0.00/міс)**.
